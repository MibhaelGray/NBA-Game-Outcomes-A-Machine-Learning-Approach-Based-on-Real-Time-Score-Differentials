1. Introduction¶

For my project, I wanted to analyze NBA game data to build predictive models that can determine game outcomes based on in-game statistics. The dataset I'm using provides detailed "snapshots" of games at regular time intervals, tracking the score, time remaining, and other metrics throughout each game.

As a basketball fan, I've always been fascinated by the concept of win probability and how it fluctuates during games. Commentators often discuss how certain moments are "turning points" in games, but I wanted to explore this analytically. My goal is to determine how accurately we can predict the final outcome of an NBA game based on the state of the game at various time points, and to identify which factors are most important in making these predictions.

2. Primary Goals¶

  1. Build machine learning models that can accurately predict which team will win an NBA game based on in-game statistics like score differential, time remaining, period, and other features in my dataset.

  2. Analyze how win probability evolves throughout games and determine at what point in games predictions become reliable.

  3. Compare the performance of different machine learning approaches (logistic regression, random forests, gradient boosting, etc) to see which works best for this prediction task.

  4. Identify key moments or thresholds during games that have the strongest correlation with final outcomes, essentially finding the statistical "point of no return" in NBA games.

I believe this analysis will provide interesting insights into basketball game dynamics and potentially reveal patterns that aren't obvious to casual observers of the game.

6. Handling Missing Values¶

Handling Missing Values in Overtime Games:

Upon initial exploration, I identified 1,792 missing values in my dataset's scoring-related features. Further investigation revealed a systematic pattern: these missing values occurred exclusively in overtime periods (specifically when games reached a 5th period). The missing data spans from the 12:00 to 5:30 mark (minutes and seconds remaining) or equivalently from the 0 to 390th second mark of overtime periods. This pattern exists because NBA overtime periods are only 5 minutes long, rather than the standard 12 minutes of regular quarters. Since overtime games constitute a relatively small proportion of my dataset, there aren't enough unique overtime period snapshots to enable reliable model training for these scenarios. Therefore, to maintain data consistency and model reliability, I decided to exclude all overtime games from my analysis. This approach allows me to focus on regulation-time game dynamics while eliminating the missing value issue entirely, rather than implementing imputation methods that might introduce bias into the overtime period data.

10. Set up K-fold Cross-validation¶

In [7]:
# Using GroupKFold so that the data isn't split randomly. 

from sklearn.model_selection import GroupKFold, GridSearchCV
cv = GroupKFold(n_splits=5)

# This is how GroupKFold will split the data
# Unique games in the training set with the specific feature columns we want
train_game_ids = df_unique.loc[train_mask, 'GAME_ID']

To ensure that my predictive models could generalize well to new, unseen games, I carefully split my dataset into separate training and test sets. Importantly, instead of randomly splitting individual snapshots from the games, I grouped all data from the same game together and used about 80% of the games for training the models, while reserving the remaining 20% for testing their performance. This approach is crucial because each game contains many snapshots taken at different times, and if snapshots from the same game appeared in both the training and test sets, the model could “cheat” by learning patterns specific to those games, leading to overly optimistic results. By splitting on unique games, I made sure that the test set truly represented new, unseen games. Additionally, during model development, I used a technique called cross-validation, which involves dividing the training data into several smaller folds, training the model on some folds while validating it on others, and repeating this process multiple times. Cross-validation helps ensure that the model’s performance is consistent and not just a result of a lucky or unlucky split.

For each type of model, I experimented with a range of parameter values to find the best settings. For logistic regression, I adjusted the “C” value, which controls how much the model tries to avoid mistakes versus keeping things simple—smaller values make the model more cautious, while larger values let it fit the data more closely. I also tried two different ways for the model to handle mistakes: L1 penalty (also known as Lasso), which can help the model ignore unimportant features, and L2 penalty (also known as Ridge), which spreads the penalty more evenly across all features. I also tested two different algorithms for solving the problem. For the random forest model, I varied how many decision trees the model would use (more trees can make the model more stable), how deep each tree could grow (deeper trees can capture more detail but risk overfitting), and how much data is needed to make a split or a final decision at the end of a branch. For gradient boosting, I tweaked how many rounds of boosting to use, how big a step the model takes each time it learns (the learning rate), how complex each tree can be, and whether to use all the data or just a portion for each round. For the support vector machine, I changed the “C” value, which, like in logistic regression, balances caution and flexibility. By trying out these different settings, I was able to find the combinations that helped each model make the most accurate predictions, without being too simple or too complex.

16. Conclusion¶

In this project, I set out to analyze NBA game data and build predictive models to estimate the probability of a team winning at various points during a game. By carefully cleaning the data, handling missing values, and engineering features such as score differential, momentum, and team win percentages, I was able to demonstrate the incredibly dynamic nature of NBA basketball. My exploratory data analysis revealed that most games remain competitive until late in the contest, and that both the size and timing of a lead play crucial roles in determining win probability. The EDA also highlighted the importance of home court advantage and how its impact fluctuates throughout the game.

After fitting and tuning several machine learning models, including logistic regression, random forest, gradient boosting, and support vector machines, I found that all models performed similarly well, with gradient boosting achieving the highest ROC AUC. The results suggest that the features engineered from in-game statistics are highly predictive of game outcomes, and that even relatively simple models can perform well with well-prepared data. Looking ahead, future work could explore more granular play-by-play data, incorporate player-level statistics, or apply these models to live win probability tracking during games. Overall, this project demonstrates the power of data-driven approaches in understanding and predicting the ebb and flow of NBA games.

While my models achieved impressively high accuracy and ROC AUC scores, I realized that these metrics are heavily influenced by the many “easy” snapshots in the dataset, such as late-game situations where the outcome is nearly certain due to a large lead. In reality, predicting the winner early in the game or when the score is close is much more challenging, and the model’s performance in those scenarios is likely lower than the overall metrics suggest.
